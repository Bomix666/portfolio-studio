# Umbra — сайт-портфолио студии

Продакшн-сайт для студии веб-разработки и digital-дизайна. Сайт сам по себе главный кейс
портфолио: кинематографичный первый экран с видео, 3D-объект на WebGL в реальном времени,
редакционная подача кейсов, живой образец дизайна и разработки и настоящая форма заявки
с серверной частью.

Язык сайта — русский (`<html lang="ru">`, `ru_RU` в мета-данных).

> **«Umbra» — временное название студии.** Всё, что нужно заменить перед запуском, собрано
> в разделе [Чек-лист запуска](#чек-лист-запуска).

## Стек

| Зависимость | Зачем |
| --- | --- |
| **Next.js 16** (App Router, Turbopack) | Статическая генерация страниц, route handlers для API, соглашения для метаданных, OG, sitemap |
| **React 19** + **TypeScript** | Интерфейс и сквозные типы (контракт API общий для клиента и сервера) |
| **Tailwind CSS 4** | Дизайн-токены в CSS (`@theme`), container queries для живого образца |
| **motion** (`LazyMotion` + `m`) | Анимации по скроллу, layout-переходы, появление/исчезновение; движок грузится после гидрации |
| **three** + **@react-three/fiber** + **@react-three/drei** | 3D-объект: стеклянные слои, световое кольцо, процедурное освещение. Отдельный чанк, грузится при скролле |
| **lenis** | Плавный скролл (выключается при «уменьшении движения», на тач-устройствах — нативная инерция) |
| **zod** (`zod/mini`) | Одна схема валидации для клиента и сервера (~6 КБ gzip в браузере) |
| **lucide-react** | Иконки (иконки Instagram и Telegram нарисованы в стиле Lucide: в Lucide v1 брендовых иконок нет) |
| **server-only** | Не даёт серверному коду и секретам попасть в клиентский бандл |

Без UI-китов, CMS, аналитики и GSAP — только то, что действительно работает на задачу.

## Шрифты

- **Noto Serif Display** — заголовки. Сужена по оси `wdth` до 72 %, вес 350: так она сохраняет
  узкий редакционный характер Instrument Serif из исходного референса, у которой нет кириллицы.
- **Geist** — интерфейс и текст, **Geist Mono** — подписи и метки. Оба с кириллицей.

Все шрифты самостоятельно раздаются через `next/font` — никаких запросов к внешним CDN.

## Форма заявки

**Клиент:** видимые подписи, проверка при уходе с поля (и живая перепроверка после первой
ошибки), фокус на первом неверном поле, `aria-invalid`/`aria-describedby`, состояние загрузки
с `aria-busy`, баннер ошибки с запасной почтой, анимированное сообщение об успехе, которое
получает фокус, нативная клавиатурная навигация в группах-переключателях.

**Сервер — `POST /api/contact`** выполняет по порядку:

1. Проверку источника (`Origin` / `Sec-Fetch-Site`) — защита от CSRF для эндпоинта без cookies
2. Обязательный `Content-Type: application/json` (кросс-доменный браузерный запрос требует preflight, который никогда не одобряется)
3. Лимит — 5 отправок за 10 минут на клиента (`src/lib/server/rate-limit.ts`)
4. Проверку конфигурации — отвечает **503** с безопасным текстом, вместо того чтобы молча потерять заявку
5. Чтение тела с ограничением размера (16 КБ)
6. Санитизацию — удаление управляющих, невидимых и bidi-символов, CR/LF из однострочных полей (защита от инъекции заголовков)
7. Honeypot — «успех» для бота, заявка тихо отбрасывается
8. Zod-валидацию — ту же схему, что и в браузере
9. Подписанный токен формы (HMAC-SHA256, выдаётся `GET /api/contact/token`) — отклоняет поддельные и просроченные токены и тихо отбрасывает заявки, заполненные быстрее 3 секунд
10. Контент-эвристики — ссылки в имени/компании, больше 3 ссылок в сообщении
11. Доставку через выбранный адаптер; ошибки провайдера дают **502** и логируются без содержимого заявки

У каждого ответа стабильный код `error` и сообщение на русском, которое безопасно показывать.

### Подключение почтового провайдера

Доставка спрятана за небольшим интерфейсом (`LeadDelivery` в `src/lib/server/mail/types.ts`) и
выбирается переменной `CONTACT_PROVIDER`:

| Провайдер | Переменные |
| --- | --- |
| `resend` | `RESEND_API_KEY`, `CONTACT_TO_EMAIL`, `CONTACT_FROM_EMAIL` (подтверждённый отправитель) — REST API, без SDK |
| `webhook` | `CONTACT_WEBHOOK_URL`, опционально `CONTACT_WEBHOOK_SECRET` (подпись тела в `X-Signature: sha256=…`) — Slack, Zapier, Make, n8n, CRM, Telegram-бот через прокси |
| `console` | Только для разработки: пишет в лог обезличенную сводку |

Чтобы добавить SMTP (или Postmark, SES…), реализуйте `LeadDelivery.deliver()` в
`src/lib/server/mail/providers.ts` и зарегистрируйте его в `mail/index.ts`. Роут менять не нужно.

### Для продакшна

- `CONTACT_FORM_SECRET` **обязателен** (32+ случайных символа). Без него и без настроенного
  провайдера форма отвечает 503 и показывает почту для связи.
- Хранилище лимитов по умолчанию — в памяти: корректно для одного Node-процесса и «на инстанс»
  в serverless. Для нескольких инстансов реализуйте `RateLimitStore` на Redis/Upstash/KV.
- `TRUST_PROXY=true` ставьте только за прокси, который выставляет `X-Forwarded-For`
  (Vercel, Cloudflare, ваш Nginx), — тогда лимиты считаются по IP.
- **152-ФЗ.** Для аудитории в РФ обычно требуется отдельное согласие на обработку персональных
  данных (чекбокс со ссылкой на документ). Уточните у юриста; добавить чекбокс — небольшая доработка
  схемы и формы.

## Заголовки безопасности

Задаются в `next.config.ts`: Content-Security-Policy (`default-src 'self'`, ни одного внешнего
источника — шрифты раздаёт `next/font`, ролик и 3D-окружение локальные), HSTS (в продакшне),
`X-Frame-Options: DENY` + `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`,
`Permissions-Policy`, `Cross-Origin-Opener-Policy`, без `X-Powered-By`.

Скрипты разрешают `'unsafe-inline'`, потому что страницы генерируются статически (nonce требует
динамического рендеринга). Строгий CSP на nonce описан в
`node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`.

## Производительность

- Ролик первого экрана перекодирован из присланного файла 20 МБ / 16 Мбит/с в AV1/WebM
  (1,1–2,0 МБ) с запасным H.264 (1,3–2,9 МБ); разрешение выбирается под экран; видео на паузе
  вне экрана и в фоновой вкладке; при «уменьшении движения» и Save-Data не грузится вовсе.
  Сначала рисуется приглушённый постер — быстрый LCP.
- Three.js (~250 КБ gzip) вынесен в отдельный чанк и грузится, только когда посетитель начинает
  скроллить к секции «О студии»; рендер идёт, только пока секция на экране; разрешение
  подстраивается через `PerformanceMonitor`; на телефонах облегчённые материалы; при «уменьшении
  движения» рисуется один кадр по запросу. Пока сцена грузится (или если WebGL нет), показывается
  CSS-версия объекта.
- Движок Motion и живой образец грузятся лениво; обложки проектов — серверные компоненты;
  появление при скролле — CSS + один общий `IntersectionObserver` вместо десятков анимационных
  компонентов.
- Начальный JS ≈ 186 КБ gzip (было 291 КБ до оптимизации). Все страницы статические.

Lighthouse (локальная продакшн-сборка, headless Chrome **без GPU** — композитинг программный,
поэтому TBT завышен):

| | Производительность | Доступность | Практики | SEO |
| --- | --- | --- | --- | --- |
| Мобильный (CPU ×4, медленный 4G) | 76–77 | 100 | 100 | 100 |
| Десктоп | 80 | 100 | 100 | 100 |

Реальный LCP 0,8–0,9 с, CLS 0. После деплоя перепроверьте на живом сайте (PageSpeed Insights).

## Доступность

Семантические ориентиры и порядок заголовков, ссылка «Перейти к содержимому», видимый фокус
везде, полная клавиатурная навигация (табы и стрелки, группы-переключатели, стрелки в схеме
стека, Esc закрывает меню, фокус удерживается через `inert`, пока меню открыто), live-регионы
для статуса формы и панели стека. `prefers-reduced-motion` выключает плавный скролл, кастомный
курсор, видео (остаётся постер), закрепление секций и все трансформации — каждая секция сразу
показывается в финальном виде. Кастомный курсор работает только с мышью и возвращает системный
курсор над полями формы.

## Русская типографика

`npm run typograf` — мини-типограф для исходников (`scripts/typograf.mjs`): привязывает короткие
слова («в», «и», «на», «по»…) к следующему слову неразрывным пробелом, ставит неразрывный пробел
перед тире и не даёт разорвать число и единицу («4 800 ₽», «390 px»). Работает только со строками,
где есть кириллица, и безопасен для повторного запуска. Запускайте после правки текстов.
